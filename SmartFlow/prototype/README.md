# SmartFlow — работающий локальный MVP

Минимальная версия исходной идеи SmartFlow: обработка и согласование счетов поставщиков. Учебный прототип, один пользователь, один компьютер. Демо-роли «Бухгалтер» и «Руководитель» доступны в одном интерфейсе.

## Быстрый запуск

Нужен Python 3.10–3.13 и современный браузер. Для первой установки зависимостей нужен интернет. После установки приложение работает локально без внешних API.

**Windows:** распакуйте архив и дважды щёлкните `start_windows.bat`. Если Python не установлен, установите его с python.org, включив Add Python to PATH. При первом запуске скрипт создаст `.venv` и установит зависимости. Затем откройте http://127.0.0.1:8000.

**macOS / Linux:** откройте терминал в папке `prototype` и выполните `bash start.sh`. Затем откройте http://127.0.0.1:8000.

**Вручную:**

```text
python -m venv .venv
```

Windows:
```text
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python app.py
```

macOS / Linux:
```text
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python app.py
```

Окно сервера оставляйте открытым. Для остановки нажмите Ctrl+C. Если порт занят, задайте другой порт: Windows `set PORT=8002`, macOS/Linux `export PORT=8002`, затем повторите запуск и откройте указанный порт.

## Демонстрация за 3 минуты

1. Нажмите «Счёт на 24 500 ₽»: откроется карточка демонстрационного документа.
2. Сверьте номер, дату, поставщика, ИНН и сумму с текстом справа. При необходимости исправьте значения.
3. Нажмите «На согласование». При пороге 50 000 ₽ документ направляется бухгалтеру.
4. Нажмите «Согласовать», вернитесь в реестр и выгрузите CSV.
5. Откройте пример на 85 000 ₽. Его маршрут — руководитель.
6. Верните документ с комментарием, исправьте поставщика и отправьте повторно.
7. В разделе правила измените порог. Он применяется при следующей отправке, уже отправленные документы не меняются.

Дополнительно загрузите файлы из `examples`: два TXT и по одному PDF и DOCX. Все реквизиты вымышленные. Встроенный пример и файл из папки могут считаться разными документами: проверка дублей сравнивает байты файла, а не номер счёта.

## Возможности и ограничения

- PDF с текстовым слоем, DOCX и UTF-8 TXT; не более 5 МБ, PDF — не более 30 страниц.
- Извлечение по шаблонам: «Счёт № … от ДД.ММ.ГГГГ», «Поставщик: …», «ИНН: …», «Итого к оплате: …». Для других форматов поля могут остаться пустыми; заполните их вручную.
- Пять реквизитов обязательны перед сохранением и отправкой. Дата проверяется на существование; ИНН — на 10/12 цифр, без проверки контрольного числа. Сумма положительная, до двух знаков после запятой, валюта RUB.
- Порог задаётся без кода. Сумма ≤ порога — бухгалтер; больше порога — руководитель.
- Состояния: Проверка → На согласовании → Согласован / Возвращён → На согласовании. Изменения после отправки возможны только после возврата. Согласованный документ окончателен для этого прототипа.
- Поиск, фильтр статуса, CSV всего реестра, история действий, защита от повторной загрузки идентичного файла.
- SQLite хранит извлечённый текст, реквизиты, состояния, историю и правило. Исходный PDF/DOCX как файл не архивируется.
- Нет OCR, обученной ML-модели, интеграций с 1С/почтой, авторизации, разграничения прав и реальных уведомлений. Кнопка согласования имитирует действие соответствующего участника.
- Это локальная демонстрация, а не готовый облачный сервис. Сервер слушает только 127.0.0.1. Для реального многопользовательского пилота нужны авторизация, роли, резервные копии и надёжный сервер.

## Данные

Файл `data.sqlite3` создаётся рядом с `app.py` при первом запуске. В поставке его нет, реестр пустой. Данные сохраняются между запусками. Для чистого демо остановите сервер и переименуйте базу, например в `data_backup.sqlite3`; при запуске создастся новая пустая база. Не удаляйте базу, если данные нужны.

Для отдельной базы задайте переменную `SMARTFLOW_DB`. Порог по умолчанию — 50 000 ₽. Запись времени в истории использует локальное время компьютера.

## Структура

- `app.py` — сервер, чтение документов, правило, SQLite и HTTP API.
- `static/` — интерфейс браузера.
- `examples/` — вымышленные документы для показа.
- `requirements.txt` — две зависимости с фиксированными версиями.
- `test_app.py` — автоматическая проверка основного сценария.

Проверка: после установки зависимостей выполните `.venv/bin/python -m unittest -v test_app.py` (Windows: `.venv\Scripts\python -m unittest -v test_app.py`).

## Что изменилось относительно исходной презентации

Сквозная no-code/ML-платформа с множеством процессов сужена до счетов поставщиков. Настройка без кода представлена одним порогом согласования. Извлечение реализовано правилами; ML и OCR отложены. Сохранена идея сокращения ручной обработки документов.

Заявления о готовых клиентах, зарегистрированных правах, патентах, привлечённых инвестициях и достигнутой доходности не включены в новую презентацию как факты: подтверждающих материалов нет. Цель пилота по экономии времени 30% — гипотеза. Все иллюстрации интерфейса сняты с работающего приложения на демонстрационных данных.

## Обновление интерфейса

Компактное оформление в стиле учётных систем: жёлтая панель, меню разделов, табличный реестр и вкладки «Основное» / «История согласования». После замены файлов обновите страницу сочетанием Ctrl+Shift+R. Существующую data.sqlite3 сохраняйте.
